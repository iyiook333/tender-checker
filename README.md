# 招投标文件漏项检查工具

这是一个本地运行的招标文件检查工具，定位是**只做检查，不生成整本标书**。它把招标文件整理成四张可核对表：

1. 资格条件
2. 废标/否决条款
3. 材料清单
4. 截止时间与关键时间节点

每条结果带原文摘录和解析器生成的原文位置。模型只负责候选条款的分类和摘要，页码、段落、表格行等位置由本地解析器提供，服务端会验证引用是否真实存在。

## 设计要点：让模型的引用可证伪

LLM 在长文档抽取里最危险的失效模式不是"答得不好"，而是**编造一个看起来合理的原文位置**。
如果工具把模型给的页码直接展示给用户，用户会以为已经核对过原文，而实际上漏掉的废标条款
可能就在被编造的位置旁边。

本工具的处理方式是**不信任模型给出的任何位置信息**，具体分三步：

1. **位置由本地解析器提供。** 解析文档时每个片段都带一个 `source_id`（如 `page-3-lines-12-16`、
   `table-2-r5`）和自己的位置元数据（页码/段落/表格行列/字符偏移）。模型只被要求回传 `source_id`
   和一段原文摘录，它无从"发明"位置。

2. **摘录必须能在原文里逐字找到。** 服务端用 `evidence in segment.text` 做精确子串匹配
   （`services/extractor.py` 的 `_find_segment`）。匹配不上就判定为未通过校验。

3. **校验失败的条款降级而非丢弃。** `verified=False` 的条目会被显式标注为"待核验"，
   置信度压到 0.3 以下，严重度强制改为"待核验"，并写明"模型引用无法在原文片段中匹配"。
   用户看到的是一份标注了可信度的清单，而不是一份真假难辨的清单。

这个机制能挡住"编造内容"和"摘录正确但 source_id 张冠李戴"两类错误。它的边界也说清楚：
它只证明**这段文字确实在文件中且位于该片段**，不能证明模型的分类或摘要正确，
也不能识别"掐头去尾改变语义"的引用。所以模型输出仍然只是候选审查结果。

## 支持格式

- PDF（优先使用 PyMuPDF；如果不可用，尝试系统 `pdftotext`）
- DOCX
- TXT、MD

扫描版 PDF 如果没有文本层会提示需要 OCR，不会把空文本当作分析完成。旧式 `.doc` 暂不支持，请先转换成 `.docx` 或 `.pdf`。

## 启动

双击 `run.bat`。首次启动会创建 `.venv` 并安装依赖，之后打开 <http://127.0.0.1:8000>。

也可以手动运行：

```powershell
cd D:\tender-checker
py -3 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

## 模型配置

模型名称、协议和代理地址现在默认留空，由使用者在网页中填写。点击“测试连接”或“开始检查”前必须填写完整；工具不会因为启动服务就自动使用某个模型，也不会自动扣费。

示例配置（仅供填写参考）：

```text
模型名称：gpt-6-astra
协议：OpenAI-compatible
代理地址：http://127.0.0.1:15721/v1
```

环境变量只供你自己编写启动脚本或服务端部署时读取，不会自动填充网页表单，也不会替网页请求提供模型名称、协议或代理地址。网页中的三个字段仍必须由使用者显式填写：

```text
CCSWITCH_BASE_URL=http://127.0.0.1:15721/v1
CCSWITCH_API_KEY=PROXY_MANAGED
CCSWITCH_MODEL=gpt-6-astra
```

如果你的 CCSwitch 模型别名写作 `gpt6astro`，请在网页的模型名称中填写 `gpt6astro`。工具不会读取或展示 API 密钥，也不会把全文写入普通日志。

## 使用方式

1. 选择一个招标 PDF/DOCX/TXT/MD 文件。
2. 填写模型名、协议和代理地址。
3. 点击“开始检查”。
4. 在四个标签页中查看结果，展开每行查看原文和位置。
5. 可导出 JSON 或 CSV。

只上传招标文件时，工具输出的是“应满足要求/应提交材料”的检查清单；它不会声称已经核对某家投标人的实际材料。未来若增加材料包比对，应作为独立的漏项模式，不改变本工具不生成整本标书的定位。

## 成本与准确性说明

- 工具按文档结构分块后发送，避免把整本文件重复发给模型。**目前不做关键词预筛选**：分块只按长度拼装，候选条款的识别交给模型。（早期设计里有过关键词过滤的想法，mock 模式仍保留关键词匹配用于离线演示，但真实流程未启用。）
- 每块默认最多约 12,000 个字符；超长单段会拆分并保留原始来源标识。默认最多同时处理 1 个文件任务，每个文件的分块请求并发上限为 2；并发越高，模型余额消耗和瞬时内存占用越高。任务结果默认在进程内保留一小时，最多保留 100 个终态任务。
- 文档内容会经 CCSwitch 发往其配置的上游模型服务。请勿上传不允许出网的敏感文件。
- 模型输出是候选审查结果，不能替代招投标专业人员复核，尤其是废标条款和截止时间。
- 相对日期、多个时间节点、缺少年份或时区的日期会标记为“待核验”。
